# 🔍 오디오 왜곡 및 텍스트 하이재킹 장애 분석서 (Troubleshooting Case Study)

본 문서는 프로젝트 초기(v1.0 ~ v1.1.1)에 겪었던 두 가지 핵심 오디오 장애의 원인 규명과 수학적/음향학적 해결 과정을 보존합니다.

---

## 1. 48kHz ➔ 16kHz 미변환 슬로모션 및 피치 저하 현상

### 1.1 현상
- 사용자가 마이크로 "안녕"이라고 짧게 인사했으나, Gemini 모델이 알아듣지 못하고 침묵하거나 전혀 엉뚱한 대답을 생성함.
- 수신된 음성 패킷을 분석한 결과, 일반적인 한국어 사람의 발화 속도가 아니라 3배 늘어진 초저속 슬로모션 괴물 목소리 형태로 수음됨.

### 1.2 음향학적 분석
1. **표본화율 차이**:
   - 모바일 브라우저 및 현대 사운드 카드의 오디오 인터페이스 기본 표본화율은 **48,000Hz (또는 44,100Hz)**.
   - `getUserMedia`를 통해 획득한 오디오 스트림은 1초에 48,000개의 부동소수점 샘플을 생성함.
2. **타깃 인터페이스 규격**:
   - Gemini Live WebSocket API는 **16,000Hz 16-bit Mono PCM**을 입력 스트림으로 명시.
3. **미변환 송출 시의 왜곡**:
   - 48,000개의 샘플을 리샘플링 없이 그대로 16kHz 스트림으로 송출하면, 1초 분량의 소리를 전송하는 데 3초가 소요됨.
   - 시간축 확장: **3.0배 슬로모션 (시간 지연)**
   - 주파수축 수축:
     $$f_{perceived} = f_{original} \times \frac{16000}{48000} = \frac{1}{3} f_{original}$$
   - 음정(Pitch) 저하 계산:
     $$\Delta \text{semitones} = 12 \times \log_2\left(\frac{1}{3}\right) = 12 \times (-1.58496) \approx -19.02 \text{ 반음}$$
   - **결과**: 사용자의 모든 발화가 **1옥타브 + 7반음(완전5도)이나 강하**되어, 남성 목소리는 50Hz 이하의 초저주파 진동으로 뭉개지고, 여성 목소리는 굵은 저음 남성 목소리로 변질되어 음성 인식 모델(ASR)이 단어를 식별할 수 없었음.

### 1.3 해결책
- `VoiceCallEngine.ts`에 `downsampleTo16kHz` 선형 보간 알고리즘 탑재.
- 하드웨어 native 샘플레이트(`ctx.sampleRate`)를 측정하여 정확히 $48000 \to 16000$ (3:1) 또는 $44100 \to 16000$ (2.75625:1) 보간을 수행함으로써 음정과 재생 속도를 1:1로 원상 복원.

## 2. WebSpeech 환각 자막에 의한 모델 하이재킹 현상

### 2.1 현상
- 사용자가 조용히 듣고 있거나 가벼운 감탄사를 냈을 뿐인데, 화면에 갑자기 "치과", "사랑해", "안녕하세요 반갑습니다" 같은 뜬금없는 자막이 찍히고, AI가 "치과에 가시는군요!"라는 등 동문서답을 함.

### 2.2 메커니즘 분석
1. 초기 구조에서는 사용자 화면에 실시간 한글 자막을 보여주기 위해 브라우저의 `webkitSpeechRecognition` (WebSpeech API)을 마이크 스트림과 병렬로 띄움.
2. WebSpeech API는 배경 잡음이나 마이크 노이즈에 매우 취약하여, 잡음을 언어로 오인식(Hallucination)하여 무작위 단어를 반환함.
3. 기존 코드의 `onResult` 콜백이 이 환각 텍스트를 Live WebSocket의 `text_prompt`로 주입함.
4. Gemini Live 모델은 실시간 마이크 오디오 스트림보다 나중에 도착한 `text_prompt`에 우선순위를 부여하여 오디오를 끊고 텍스트에 응답함.

### 2.3 해결책
- **단일 오디오 소스(Single Ear) 원칙 확립**:
  - Live 통화 중에는 WebSpeech API 프로세스를 완전히 중지 (`recognition.stop()`).
  - 오직 16kHz 마이크 PCM 스트림만 구글 서버로 송출.
  - 화면의 한글 자막은 구글 Gemini Live 서버가 직접 디코딩하여 내려주는 `inputAudioTranscription` 결과만 수신하여 표시.
  - 환각 텍스트 주입 원천 차단 완료.
