## 3. 문제가 아니었던 것
- `firestore.rules`, 서버 로그인 확인(`server/auth.ts`), 녹음 경로 검사(`server/recordingPath.ts`), 피드 백업 암호화(`server/feedStore.ts`): 다시 읽었고 올바름.
- 일일 한도(`server/rateLimit.ts`: 1분 60회, 하루 1,500회, 통화 시작 60회): 그대로 유지. 이번 수정에서 건드리지 않음.
- CORS: 다른 출처에 허용 헤더를 보내지 않음(같은 출처 전용). 그대로.
- 프로젝트 지침의 `/api/analyze` 6종 실패 코드: 이 저장소에는 `/api/analyze`(사진 분석) 경로가 없음. 해당 없음.

## 4. 고치지 않은 것 (결정이나 확인이 필요)
- **통화 단가(`models.ts` `livePerMinute: 0.004`)**: 실제보다 낮아 보임 [추정]. `gemini-3.8-live`의 공식 단가를 이번에 확인하지 못해 숫자를 바꾸지 않음. 설정 → 사용량의 "예상 비용"은 실제 청구액과 다를 수 있음. Google AI Studio 청구 화면과 비교 필요.
- **아침 강의 음성·서버 예비 녹음이 `.data/`에만 있음**: 서버가 새로 뜨면 지워짐(피드 설정과 키만 Firestore 백업). 저장 위치 결정이 필요.
- **Cloud Run이 요청이 끝난 뒤 CPU를 줄이는 환경에서 강의 생성(백그라운드 작업)이 끝까지 도는지**: 코드로는 알 수 없음. 실기기 QC 항목으로 넣음.
- **`npm audit` 10건(high 8, moderate 2)**: 그대로 둠. `npm audit fix`를 돌려 보니 Firebase SDK가 새 버전으로 올라가며 딸린 패키지가 수십 개 추가됨. 실제 로그인·통화로 시험할 수 없는 환경이라 이번 PR에는 넣지 않음. 남은 것은 Firebase가 쓰는 `@grpc/grpc-js` 계열, 개발 서버용 `vite`·`esbuild`, `qs`·`re2js`·`source-map-js` 등. 실기기 QC가 끝난 뒤 따로 올리는 것을 권장.
- **허용 계정 이메일 고정**(`firestore.rules`, `server/auth.ts`, `src/services/firebase/auth.ts`): 1인 테스트판 설계. 베타 전에 바꿔야 함.
- **복기 재시도 시 기기에만 남은 조각**: 업로드에 실패해 기기(IndexedDB)에만 있는 조각은 "끝나지 않은 통화" 복기에서 읽지 않음(앱을 열 때 자동 재업로드는 함). 받아쓰기가 비면 임시 받아쓰기·대화 로그로 대체됨.
